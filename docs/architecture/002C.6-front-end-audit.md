presentation changes. The implementation retains the subsequently accepted

## Current production flow

`main.gd` owns collection, preferences, Run state and action validation.
`menus.gd` constructs views and emits intents. Preserve this boundary. First
choice remains reversible until the save API successfully commits exactly three
starter parts. The saved collection is independent of temporary powers, XP,
RPM and practice builds. An active Run locks Workshop/build actions. Preserve
stale-signal validation, draft revision/seed/claim checks and pause-origin focus.

Production boots directly into a collection title with BEGIN/Workshop, two
practice entries, Help, Settings and Quit. A fresh player passes through three
starter cards, confirmation and ownership before Workshop. Initialized players
skip the ceremony. Workshop exposes all 31 catalogue definitions (11 Blades,
9 Ratchets, 11 Bits) across three independently scrolling strips; owned cards
equip and locked cards only inspect. Practice Garage remains unrestricted and
does not grant collection ownership. Options contains master volume, mute,
screen shake and fullscreen. Run pause retains the exact suspended draft,
mutation, acquisition or combat origin. Draft and mutation cards use saved
accepted power art and authoritative claim payloads. Run results display actual
Run summary fields but flatten the final machine's powers into a text list.

## Coherent visual and information architecture

The world is a physical spinning-top workbench: dark industrial metal, worn
paint, warm contact edges and a real assembled top. Share native pixel rules,
type hierarchy, spacing, focus corners and action footer; vary composition by
screen purpose. Avoid universal centre-top-plus-glow arrangements, oversized
anonymous panels and unrelated sci-fi widgets.

Use a legible authored pixel face with intentional body/heading sizes and a
separate display mark. Do not redistribute Windows system fonts. Shared
background/frame/font/glyph assets need declared source/runtime correspondence.
Retain whole-pixel layout, nearest filtering and integer window scaling.
Component thumbnails come from actual runtime part PNGs, cropped to visible
pixels; they are inspection art, not newly invented part designs.

| View | Primary composition and action |
| --- | --- |
| Title gate | Large wordmark, physical spinning-top stage, deliberate Press Start. No hidden unlocks. |
| Hub | Run → Workshop → Play Modes → Options → Exit. Equipped machine and real collection status on the workbench. Fresh Run routes to first-top choice. |
| Workshop | Left: assembled top and three equipped slots. Right: category tabs, scrollable native component cards and selected-part inspection. Footer: Back, Practice, Launch owned top. |
| Play Modes | Quick Duel and Practice Garage only. Register future routes in code; do not display fake coming-soon multiplayer modes. |
| Options | Grouped audio/display/accessibility controls with actual values and context-aware Back. |
| Pause | Compact overlay preserving arena context; Resume remains default. Options returns to pause without advancing Run timers. |
| Draft | Existing one/two/three-card offers, authoritative rank/mutation/revision payloads and finite reroll charge state. |
| Result | End reason and survived time lead; real Run counts and final power state follow; Restart/Workshop/Hub actions are clear. |

Native layout budget: 16–24px outer margins; roughly 48px header and 30px action
footer; Workshop's left station uses ~220px and right catalogue ~370px. A
two-column catalogue can show six readable cards with 48px native component
space; scrolling reaches every item. Category state is presentation-only. Keep
`focus_collection_part(category,id)` as the focus restoration API; it activates
the required category before focusing the real card. Hidden category cards must
never enter the live focus graph.

## Integration API and ownership

Menus adds `show_title_gate(initialized=false)` emitting `enter_frontend`.
`show_collection_title(build,settings,initialized)` becomes the hub and retains
existing collection intents; `show_play_modes(build)` emits actual practice
routes. `show_collection_workshop(build,snapshot)` remains ownership-driven.
Settings may receive an optional return intent so Main owns context restoration.

Main owns boot gate/hub routing, guarded settings entry from pause, preference
schema, sound bus application and any save/reset action. Menus owns views,
presentation-only category selection, visible input hints and focus. Shared
front-end skin/registry/input-context helpers establish seams for future screen
and controller ownership without implementing a second player, co-op rules or
ownership duplication in this task.

## Implemented foundation

The final view uses a project-authored 6×10 bitmap face, two native workbench
background poses and nine 16×16 input glyphs. Three editable Aseprite masters
have source/runtime parity (125 frames, 127 tags); details and export commands
are in `docs/art/002C.6-ui-art.md`. No component or power illustration was redrawn.
The live assembled machine remains a `TopPreview`; thumbnails crop the visible
pixels of real component textures and use integer scale.

`front_end.gd` supplies the native theme, screen registry and a small optional
menu-owner seam. The default owner remains every mapped device. Keyboard and
mouse coexist with Xbox, PlayStation, mapped Nintendo and generic physical
south/east prompts. Nintendo B/A letters match the existing south/east binding;
they do not pretend a controller was physically connected during synthetic tests.

The title gate emits `enter_frontend`. The hub focuses real Run, with first-save
choice only when necessary. Workshop keeps all 31 card objects, exposes one
category at a time and makes inactive controls nonfocusable. `catalogue_tab`
metadata identifies the real category buttons; cards expose `part_category`,
`part_id`, ownership and bound intent/payload. `focus_collection_part(category,id)`
activates the category before restoring focus. The two-column grid shows six
cards; scrolling and the explicit graph reach every entry. POWER, STAMINA,
GRIP, SPEED, STABILITY and MASS retain the original derived values. Collection
and practice use the same anatomy with distinct ownership copy and intents.

`show_settings(settings,return_intent,save_tools_allowed)` displays independently
bound Master/Music/SFX sliders plus mute, shake and fullscreen. Main owns
persistence and the paused origin. SaveTools is hidden during an active Run.
`show_save_tools(snapshot,backups,status,return_intent)` shows actual saved counts
and archive status. `show_reset_confirmation(snapshot)` defaults to Cancel and
emits the exact integer `reset_token` that Main provided. The existing held-
Confirm release barrier applies across this second screen.

Help now explains the continuous Run and earned draft/reroll loop. Run results
show the actual final physical assembly, end reason, survival/director counts,
and native 16×16 power icons with compact ranks/mutation names. The combat HUD
keeps its reusable controls and spatial hierarchy; its small rank labels use
single authored Roman glyphs. Screen appearance is an 80ms opacity transition
with input already live, rather than a delay or long animation.

Initial reruns exposed obsolete test assumptions that every category remained
visible simultaneously and that the hub button was named exactly BEGIN. The
updated tests assert the intended category/focus and direct Run contracts while
retaining all existing ownership, shape/overflow, controller, held-input,
assembly-combination and combat regression checks. Final test counts and
external capture hashes are recorded in the task results, rather than duplicated
here. Human visual and physical-controller acceptance remains a separate step.
