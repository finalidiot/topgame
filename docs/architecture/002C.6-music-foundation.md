# Original music foundation — Task 002C.6

Foundry Circuit is an original 16-bar, 110 BPM composition family. A steel/pluck
four-note hook, minor-key harmonic rail and written syncopated drum patterns give
the front end and continuous Run a shared musical identity. The workshop uses
sparser glass keys and half-time percussion; pressure adds an answering upper
line and off-beat machine rhythm; bosses/late pressure add a low brassy motif
and tom cadence. The score and instruments were authored for this game, without
borrowed songs, samples, named-artist imitation or generated random cue assembly.

## Source and runtime

`assets/audio/music/foundation_score.json` is the editable score: MIDI note
numbers, beat positions/durations, chord voicings, progression, drum patterns
and arrangement gains. `tools/audio/compose_foundation.py` synthesizes its own
pad, pluck, glass, bass, brass and percussion palette. NumPy's fixed offline
noise is confined to written drum notes; the runtime uses no random generator.

The five stereo PCM16 WAVs share exactly 1,117,091 frames at 32 kHz: 34.90909375
seconds, 64 beats, 16 bars. Native import preserves stereo, sample rate and PCM
without trimming, normalization or lossy compression. Note releases wrap into
the next loop; a two-millisecond raised-cosine bridge makes the first/last PCM
sample identical without fading or padding a musical bar. Runtime loop bounds
are explicitly frame0 through frame1117091. Metadata records source hashes,
frame grid, authored event counts, RMS, peaks and seam measurements.

Regenerate using a Python with NumPy:

```powershell
python tools/audio/compose_foundation.py
python tools/audio/compose_foundation.py --verify-only
python tools/audio/compose_foundation.py --verify-only --review-dir <external-QA-audio-folder>
```

The Codex bundled Python includes NumPy. `--verify-only` compares both metadata
and regenerated PCM samples, rather than merely trusting filenames. Review WAVs
contain two uninterrupted cycles, applying the Music trim/default slider before
the existing Master fader. Detailed audio evidence belongs under external
`GyroBrothers-QA/002C.6/audio/` and `manifests/`, not Git.

## Runtime contract

`scripts/music.gd` owns one `AudioStreamPlayer` and one
`AudioStreamSynchronized` with five fixed substreams. All begin at the same
audio sample and keep playing through gain changes. Context, pressure, pause,
volume and mute never replace/seek/restart the stream. Native playback defaults
off; Main explicitly opts in for ordinary play or an isolated audio review,
keeping headless, packaged inspection and smoke boot quiet.

The public interface is `configure_playback(enabled)`, `set_context(context)`,
`observe_run(run_state, player_stats={})`, `set_paused(paused)`,
`apply_settings(settings)`, `notify_cue(kind)` and `music_snapshot()`. Contexts
are title/workshop/run/result/silent. Main supplies existing continuous-Run
census/tier/calm observations and optional existing HUD RPM, Redline and power
rank values. This controller has no battle host, save access or combat callback.

Actual absolute pressure, live/admitted elites/bosses, late director tiers,
dangerous RPM and invested/active build escalation influence only mix targets.
The opening one-rival Run remains baseline even though its pressure/budget ratio
is high. Quantized plateaus, a deadband, rise/release evidence and a two-second
hold prevent rapid observations from thrashing. A genuinely admitted boss may
rise immediately; release still waits for stable evidence. A new Run resets
its adaptive profile while the common audio transport continues. Pause/drafts
subdue the Run to35% and keep musical chronology intact.

## Mix and bounds

Music sends to its own Music bus and then Master. Its baseline trim is-8 dB,
default Music slider55%; Master/SFX/mute preferences remain Main/Sound-owned.
The maximum authored full-boss sum is0.5825 peak (-4.69 dBFS), with zero clipped
samples. Normal/pressure/boss source RMS are-22.11/-19.88/-16.94 dBFS. Music
offers a temporary4 dB duck for actual heavy/major cues and a12 dB, 0.30-second
window for the existing quiet low-RPM warning. No accepted SFX sample, priority,
cooldown, pitch or gain is altered by this controller.

Cost is bounded: five cached PCM streams (22,341,820 audio bytes), one native
player, five gain updates and at most64 diagnostic events. All envelopes live
in presentation time; no gameplay mathematics, state or random streams change.

## Verification

`tests/test_music.gd` checks real imported PCM grids, adaptive evidence/holds,
independent Music mute/ducking, native-playback default gating and exact seeded
combat/RPM/director/RNG parity. Its actual Godot `mix_audio()` check compares
synchronized output against five uninterrupted independent reference cursors
while gains change and the loop boundary wraps. Godot WAV `get_loop_count()`
returns zero by design, so actual cursor wrap and PCM equivalence are checked.

`tests/test_music_native.gd` is an explicitly gated audio review fixture. With
`--allow-native-audio`, a real audio driver and external report/recording paths,
it records production Music/SFX buses, checks sustained non-silent PCM and
transport continuity through contexts/pressure/pause, and captures real heavy
and low-RPM cues. Its controlled observation dictionaries are not gameplay
footage. The task's combined presentation movie must separately use actual Run
observations and carry a non-silent audio stream.

API behavior is grounded in Godot's official
[synchronized stream documentation](https://docs.godotengine.org/en/stable/classes/class_audiostreamsynchronized.html),
[WAV documentation](https://docs.godotengine.org/en/stable/classes/class_audiostreamwav.html)
and [native synchronized mixer implementation](https://github.com/godotengine/godot/blob/master/modules/interactive_music/audio_stream_synchronized.cpp).
Automated waveform/mixer results establish technical continuity and headroom;
auditory quality and final cue balance remain human review items.
