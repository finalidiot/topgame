# Task 002C.6 front-end art

The menus use a steel workbench, an empty rotor service tray and original native
bitmap lettering. The assembled playable top is drawn separately by TopPreview;
there is no baked top illustration substituting for the live assembly. Broad
dark areas support the menu text instead of competing with it. Placed chips and
fasteners describe the bench material without a random surface-noise layer.

## Editable masters and runtime exports

| Editable Aseprite master | Native cell and poses | Runtime |
| --- | --- | --- |
| `assets/source-art/ui/foundry_small.aseprite` | 6×10; 114 named Unicode frames | `assets/ui/foundry_small.png`, `.fnt`, `.json` |
| `assets/source-art/ui/frontend_background.aseprite` | 640×360; title and hub/workshop | `assets/ui/frontend_background.png`, `.json` |
| `assets/source-art/ui/input_glyphs.aseprite` | 16×16; nine physical input symbols | `assets/ui/input_glyphs.png`, `.json` |

Each saved master has editable named layers, named frame tags, a slice pivot and
explicit frame timing. Runtime JSON records native cell dimensions, atlas
columns, source path, layer names, tags, pivots and timing. Source sheets contain
straight pixel masks and integer vertices. No resampling, raster rotation,
vector conversion, image generator or system font is involved in production.

The background atlas is **1280×360**, two horizontal cells. `title` is frame 0.
`hub` and `workshop` both select frame 1. The title station is centered at
x450/y226 underneath the live top near x450/y195. The hub station is centered at
x130/y198 underneath the live top near x130/y166. Shared header y0–31 and footer
y322–359 stay flat. The hub's right area x254–624 stays quiet under menu panels.

## Type and input symbols

Foundry Small is an original project-authored bitmap font, covered by the
repository licence. Its letter masks were drawn explicitly for this project.
It carries no Windows, commercial font or outside typeface raster. Uppercase,
lowercase, digits and punctuation have individual pixel drawings. Lowercase
has a reduced x-height, open counters, ascenders and descenders. Title lettering
uses the same industrial construction enlarged only by an integer multiple.

- Native font size: **10 px**; baseline: **8 px**; line height: **10 px**.
- Monospaced advance: **6 px**; drawable glyph cell: **6×10**.
- ASCII **U+0020–U+007E**, plus nonbreaking space, degree, plus/minus,
  multiplication, en/em dashes, typographic single/double quotes, bullet,
  ellipsis, four directional arrows and compact Roman ranks U+2160–U+2162.
  Each Roman rank occupies one six-pixel advance; III does not require three
  ASCII glyphs that would overflow the existing small HUD rank box.
- Use **10, 20, 30, 40 or 50 px** sizes, nearest filtering and integer positions.
  Font width is six pixels per character at 10 px; size20 doubles that width.
  Wrapping and fit must be measured with the actual FontFile. Do not force a
  long line into an undersized panel by rendering at a fractional size.
- BMFont texture contains only a white alpha mask. Text tint belongs to the UI.

The input atlas is **144×16**, nine horizontal cells. Its tags are `key_enter`,
`key_escape`, `pad_south`, `pad_east`, `dpad`, `pad_back`, `pad_start`, `pad_cross`
and `pad_circle`. `pad_bottom` aliases `pad_south`. Each uses a deliberately
small symbol and negative space. Enter shows the return arrow, Escape shows
ESC, Xbox style face buttons show A/B, PlayStation style face buttons show
cross/circle. The d-pad is a physical cross; back uses overlapping panels and
start uses three menu lines. Input mapping determines the displayed family;
these pictures do not change controller bindings. The mapped Nintendo profile
selects the B letter for physical south/Confirm and A for east/Back, matching
the existing binding rather than the Xbox atlas tag names.

## Artist workflow and parity

Edit the saved masters in Aseprite, preserving cell sizes, named tags and pivots.
The normal command exports the actual saved source without reconstructing it:

```powershell
python tools/art/build_front_end.py
```

The reconstruction recipe runs **only** with explicit `--author`; it overwrites
these three UI masters. Do not use that flag while exporting artist edits.

```powershell
python tools/art/build_front_end.py --check --report "C:\GPT GAME BUILDING\GyroBrothers-QA\002C.6\manifests\002c6_ui_source_runtime_parity.json"
python tools/art/build_front_end.py --check --preview "C:\GPT GAME BUILDING\GyroBrothers-QA\002C.6\images\002c6_ui_assets.png"
```

`--check` is read-only for production. It checks runtime pixels and metadata
against saved sources, then opens every master with the actual Aseprite CLI and
compares every exported pixel, layer, tag, pivot and frame duration. It also
checks full printable ASCII coverage and exact BMFont metrics. It accepts
`--aseprite`, then the shared `TOPGAME_ASEPRITE`/PATH/local installation resolver.
QA report and inspection image paths must be external to the repository.

The current production check passed using Aseprite 1.3.18.6-x64: all three masters,
125 frames, 127 tags, native/runtime pixels and metadata identical. The external
inspection sheet includes both 1× and integer-scaled font samples. Runtime
rendered menu captures remain the acceptance evidence for placement and fit.

An isolated Godot 4.7.2 import/runtime probe passed every ASCII and supplementary
glyph. `Spinning Metal` measures exactly 84/168/252/336 px wide at 10/20/30/40 px;
the native ascent/descent is 8/2 px. Import and runtime logs live externally at
`002C.6/logs/002c6_ui_font_import.log` and `002c6_ui_font_runtime.log`. That probe
uses its own tiny QA project and does not alter the live project's collection.
